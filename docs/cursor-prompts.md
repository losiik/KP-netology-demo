# Серия промптов для Cursor: подключаем ИИ к сервису КП

Стартовая точка — ветка `lecture-baseline`. В ней работают все экраны из спецификации
(вход, новое предложение, редактор, «Мои предложения»), но черновик собирает **шаблон**.
Всё остальное на лекции пишет Cursor по промптам ниже.

## Что видно до подключения ИИ

| Где | Сейчас (шаблон) | После Cursor |
|-----|-----------------|--------------|
| Метка в редакторе | `⚙ Собрано по шаблону` (серая) | `✦ Подготовил ИИ` (фиолетовая) |
| Колонка «Как создан» в «Моих предложениях» | у всех документов «шаблон» | новые документы — «ИИ», старые остаются «шаблон» |
| Текст черновика | одинаковые заголовки и строки | живой деловой текст, факты те же |
| Кнопка «Создать черновик» | без состояния загрузки | «ИИ пишет черновик…», кнопка заблокирована |
| Проверка фактов | нет | панель с ✓ и ⚠ под редактором |
| PDF | нет | кнопка «Скачать PDF», готовый документ |

Метка источника уже заложена в коде: сервер хранит `source` (`template` / `ai`),
интерфейс показывает её через [SourceBadge.jsx](../frontend/src/components/SourceBadge.jsx).
Cursor достаточно вернуть `source: "ai"`, и оба места изменятся сами.

## Перед записью

1. В корне проекта есть `.env` со строкой `AI_API_KEY=...` (ключ DeepSeek). Файл исключён из Git.
   **Ключ не показываем на экране и не вставляем в чат Cursor.**
2. Чистая база: остановить бэкенд и удалить `backend/data/kp.sqlite3`.
3. Создать ветку для записи, чтобы `lecture-baseline` осталась нетронутой:
   ```bash
   git switch lecture-baseline
   git switch -c lecture-ai
   ```
4. Запустить бэкенд (PyCharm → `backend/run.py` → Run) и фронтенд (`cd frontend && npm run dev`).
5. Для контраста «до/после» заранее создать и сохранить один черновик по шаблону:
   войти как `anna`, «Подставить пример», «Создать черновик», «Сохранить».

После каждого шага фиксируем результат, чтобы было куда откатиться:

```bash
git add -A
git commit -m "Шаг N: ..."
```

Если шаг пошёл не так, убрать незакоммиченные правки Cursor (их можно вернуть через `git stash pop`):

```bash
git stash -u
```

> После того как Cursor добавит новые библиотеки, установите их
> (`.venv\Scripts\python -m pip install -r backend\requirements.txt` или `npm install` в `frontend`)
> и перезапустите бэкенд. После изменения `.env` бэкенд тоже нужно перезапустить.

## Шаг 1. Подключаем модель

Слайды «Запрос ИИ на подключение функции» и «Инструкция для генерации предложения».
Первый абзац — текст со слайда, ниже — детали нашего проекта.

```text
Подключи генерацию только на сервере. Бери ключ из AI_API_KEY. Не выводи его
в код браузера и логи. Добавь проверку входа, полей, длины и частоты запросов,
состояние загрузки и безопасный повтор. Покажи, где задать секрет, и предложи
проверки. Не проси прислать значение ключа в чат.

Детали проекта:
- Модель — DeepSeek, у неё OpenAI-совместимый API. Ключ лежит в .env в корне
  проекта (файл уже исключён из Git). Имя модели вынеси в AI_MODEL, значение
  по умолчанию возьми из документации DeepSeek. В .env.example — только имена
  переменных.
- Вызов модели вынеси в отдельный модуль backend/app/ai_draft.py. Обработчик
  backend/app/drafts.py по-прежнему проверяет поля и считает сумму через
  calculate_total, а вместо build_template_draft вызывает модель.
- Постоянная инструкция для модели: «Составь черновик из переданных данных.
  Сохрани услуги, цены и сроки. Не добавляй скидки, гарантии и новые условия.
  Структура: задача, работы, стоимость, срок, условия». Данные формы и готовую
  итоговую сумму передавай отдельным сообщением. Текст модель пишет целиком
  сама, живым деловым языком, без Markdown.
- Ограничения: не больше 5 генераций в минуту на пользователя и одна
  генерация за раз.
- В ответе обработчика верни source: "ai" — интерфейс уже умеет показывать
  метку «Подготовил ИИ». Если модель недоступна, верни понятную ошибку.
  Шаблон молча не подставляй.
- Интерфейс: пока идёт генерация, кнопка «Создать черновик» заблокирована
  и показывает «ИИ пишет черновик…», в редакторе виден индикатор загрузки.
  При ошибке введённые данные остаются в форме и есть кнопка «Повторить».
- Тесты не должны обращаться к настоящей модели — подмени вызов.
```

**На экране:**
- Справа в Cursor — новые файлы и построчные правки в `drafts.py`, `OfferPage.jsx`, `OfferForm.jsx`.
- В приложении после «Создать черновик» кнопка блокируется, появляется загрузка.
  Затем приходит живой текст с меткой **✦ Подготовил ИИ**.
- После «Сохранить» в «Моих предложениях» рядом со старым документом «шаблон»
  появляется документ «ИИ».

**Проверяем вживую (слайд «Как проверить правку агента в Cursor»):**
1. Дважды быстро нажать «Создать черновик» — должен появиться один черновик.
2. 80 000 ₽, 15 рабочих дней и предоплата 50% в тексте совпадают с формой.
3. Разработка → 60 000: итог в тексте 90 000 ₽. Сумму посчитал код, а не модель.
4. Временно испортить ключ в `.env` и перезапустить бэкенд. Появится понятная ошибка
   и «Повторить», данные формы на месте.
5. В DevTools → Network в ответах нет ключа.

## Шаг 2. Приёмка: проверка фактов кодом

Слайд «Приёмка ИИ-функции»: услуги, суммы и сроки совпадают с исходными данными,
ИИ не добавляет отсутствующие сведения.

```text
Добавь автоматическую проверку черновика по исходным данным формы. Проверку
делает код на сервере, а не модель.

Проверяй, что в тексте есть:
- каждая услуга и её цена;
- итоговая сумма, посчитанная приложением;
- срок;
- дополнительные условия, если они заданы.
И что в тексте нет слов «скидка», «гарантия», «бесплатно», если их не было
в исходных данных.

Результат возвращай вместе с черновиком. В интерфейсе под редактором покажи
панель «Проверка черновика»: зелёная галочка у совпавшего пункта, жёлтое
предупреждение у расхождения с пояснением. Если менеджер поправил текст,
пусть кнопка «Проверить ещё раз» перепроверит текущую редакцию.
Сохранение документа не блокируй — решение принимает менеджер.
```

**На экране:** под редактором появляется панель с ✓ по каждой услуге, сумме и сроку.

**Проверяем вживую:**
1. Поменять в редакторе «80 000» на «70 000» и нажать «Проверить ещё раз».
   Итог станет ⚠ с пояснением.
2. Дописать «Скидка 10%» — появится предупреждение о новом условии.
3. Вернуть текст — снова всё зелёное.

## Шаг 3. Готовый PDF

По спецификации PDF не входит в MVP. Показываем его как следующую итерацию.
Заодно хороший повод обсудить, почему для проверки гипотезы он не обязателен.

```text
Добавь в редактор кнопку «Скачать PDF». PDF собирается в браузере из текущего
текста редактора — вместе с ручными правками менеджера.

Используй библиотеку pdfmake: её встроенный шрифт Roboto поддерживает
кириллицу и знак ₽, шрифты вручную подключать не нужно.

Оформи PDF как документ агентства:
- шапка: «Предложения» с бирюзовой полосой слева и сегодняшняя дата;
- первая строка текста — крупный заголовок;
- короткие строки без точки в конце (Задача, Работы, Стоимость, Срок,
  Условия) — заголовки разделов, жирным;
- строка с «Итого» выделена крупнее;
- внизу мелким шрифтом: «Черновик подготовлен с помощью ИИ и проверен
  менеджером».
Имя файла: КП_<клиент>_<дата>.pdf. Серверную часть не меняй.
```

**На экране:** кнопка «Скачать PDF» рядом с «Сохранить» и «Скопировать».
Скачанный файл открываем в браузере — это оформленный документ, а не просто текст.

**Проверяем вживую:**
1. Дописать в редакторе строку и, не сохраняя, нажать «Скачать PDF» — правка есть в файле.
2. Кириллица, «ёлочки» и знак ₽ отображаются корректно.

> pdfmake 0.3 с кириллицей проверен заранее: заголовок «Коммерческое предложение
> для кофейни «Зерно»» и «Итого 80 000 ₽.» выводятся без настройки шрифтов.

## Если что-то сломалось: как описать ошибку

Слайд «Как описать ошибку ИИ-разработчику». Шаблон сообщения:

```text
Ошибка. Действие: изменил текст в редакторе и нажал «Сохранить».
Ожидание: после обновления страницы вижу свои правки.
Факт: после обновления вернулся старый текст.

Исправь только эту ошибку, новых функций не добавляй. После исправления
проверь: правки остаются после обновления страницы, генерация работает
как раньше, исходные данные предложения не изменились.
```

Подставьте своё действие, ожидание и факт.

## Финальная приёмка (слайды «Как понять, что MVP работает» и «Приёмка ИИ-функции»)

- [ ] Пользователь проходит путь: данные → черновик ИИ → правка → сохранение → копирование.
- [ ] Услуги, суммы и сроки в тексте совпадают с формой. Скидок и гарантий нет.
- [ ] Итог считает код: при цене разработки 60 000 итог 90 000 ₽.
- [ ] Во время генерации повторный запрос заблокирован.
- [ ] При сбое API введённые данные сохраняются, есть повторная попытка.
- [ ] Сохранённый документ открывается после обновления страницы и повторного входа.
- [ ] `boris` не открывает документ `anna` по прямой ссылке.
- [ ] Ключа нет в браузере, в логах и в Git (`git status` не показывает `.env`).
